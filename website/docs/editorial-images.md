## How images flow into the site

1. `npm run images:import -- --slot <slot> --src <file> [--alt …] [--prompt …] [--version N]`
   (`scripts/import-editorial-image.mts`) reads the source (never modified), writes one WebP
   master (EXIF-rotated, ≤ 2000 px, metadata stripped, ≤ 450 KB) as
   `public/images/editorial/<slot>-v<N>.webp`, and records size, sha256, prompt and alt in
   `src/lib/studio/editorial-images.json`. It refuses to overwrite: a new image gets a new
   version, so cached copies of the old file never go stale.
2. `editorialImage(slot)` (`src/lib/studio/editorial-images.ts`) turns a slot into a block image
   ref (`url` + alt). A slot without a file yields an empty ref, so a page never points at a
   missing image; the section then shows its decorative panel.
3. The seed and `cms:rollout-aanbod` write those refs into the blocks. On a database that already
   has the pages, a rollout dry run shows which pages change.
4. `StudioImage` sends `/images/…` through Next's image optimiser (responsive `srcset`, WebP). Media-library images (`/api/cms/media/<id>`) stay unoptimised as before.

Editors can replace any image at any time in `/admin` with a media-library upload (*Afbeelding*
field of the block); that does not need a deploy.
