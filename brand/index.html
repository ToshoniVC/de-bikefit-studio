02 / Principles

Calm, considered, on character

Every design decision should make a recreational cyclist feel welcome and unhurried. We dress the brand in restraint, not performance.

  • QuietUse white space. Avoid dense layouts. Burgundy carries the weight; the reader sets the pace.
  • PersonalNo copy-paste. Show that the studio sees the rider, not the segment.
  • Low-thresholdNever intimidate. No jargon, no judgement, no big claims.
  • Step by stepLead the eye in clear stages. One thought per block, then a pause.
  • SubstantiveCondensed display type for what matters. Plain body type for everything else.
  • HonestPhotography over render, statement over claim, warmth over gloss.
03 / Voice & tone

Talk like a person, not a brochure

Dutch first, written for a reader who isn't a cyclist yet. Short sentences. Concrete words. Warm, but never cute. The reference tagline sets the register: "Pijnvrij fietsen begint hier."

Do

  • "Pijnvrij fietsen begint hier."
  • "Simpel, rustig en stap voor stap."
  • "Iedereen heeft een andere aanpak nodig."
  • "Kinderen mogen mee."
  • "Op jouw tempo."

Don't

  • "Optimize your biomechanical efficiency."
  • "Unlock peak performance!"
  • "Industry-leading bikefit experience."
  • "Schedule your consultation today!!!"
  • Excessive exclamation marks or capslock.

On burgundy — CSS wordmark

Use .ds-wordmark, never an inverted filter on the SVG. Footer, callouts, dark sections.

Clear space & usage

  • Minimum clear space around the mark: equal to the cap height of the wordmark on every side.
  • Minimum digital height: 40px. Below this, set the wordmark on its own line without the icon.
  • Don't recolour, invert, add shadows, outline, rotate or stretch the SVG. logo.svg is unmodified and stays that way.
  • On burgundy the CSS wordmark replaces the image. Give it the same text the image carries in alt, so nothing is lost for assistive tech.
  • logo.svg ships with its own light plate, so on a tinted surface it shows a visible panel (see the middle tile). That is the asset, not the system — a transparent production master is still outstanding.
  • The dashed "fit-line" overlay is part of the mark — it never appears on its own as a graphic device. The ring is the system's decoration instead.
05 / Colour

Burgundy is the accent

There is no separate accent hue. The brand ground doubles as the interactive colour: buttons, nav underlines, rules and bullets are all --ds-color-accent, which resolves to the sampled burgundy. Every chip below is painted with background: var(--ds-color-…), so it can never drift from the token it documents.

Usage rules

  • Burgundy is the accent. Do not introduce a second hue for emphasis — use scale, weight and the burgundy itself.
  • On light: FG for body, FG muted for secondary, FG subtle for meta. On burgundy the mirror is FG inverse / soft / muted / subtle.
  • Border inverse subtle (#8c6a5a) is a rule colour, not a text colour. Below it, contrast fails.
  • All body-text pairings clear WCAG AA: cream 11.2:1, soft 9.5:1, rose-tan 6.4:1, mauve-400 4.6:1 on the ground; ink 17:1, muted 9.1:1, subtle 5.5:1 on bone.
  • Nothing is pure white or pure black. The lightest surface is #fffdf9; the darkest is #2c0e17.
  • Recolouring the brand is a single edit to the burgundy / cream / bone primitives in tokens.css. Nothing downstream changes.

Rules

  • Display type is always uppercase and always condensed. Body type is always sentence case.
  • The italic is reserved for the tagline voice — .ds-tagline, .rich blockquote, and .hero__title em. It is never used for emphasis inside a paragraph.
  • The strapline's wide tracking (0.20–0.22em) only works at 12–13px. Do not scale it up.
  • Only what the font import actually requests is available: Barlow Condensed 400, 500, 600, 700, 800 and Inter 400, 500, 600. Don't ask for another — a heavier Inter is synthesised, not loaded.

Section vertical rhythm, desktop default.

Container & rhythm

  • Container: --ds-container-max 1400px. Prose: --ds-container-narrow 860px (used by the FAQ).
  • Gutter: --ds-gutter 24px on every band. Content never kisses the viewport edge.
  • Section rhythm: 100px block padding, dropping to 64px at ≤900px. Hero 80/60, page head 96 top / 72 bottom, callout 64.
  • Measures are ch-based: 70ch prose, 60ch lede, 22ch headings, 18ch hero title, 32ch quotes.

Radii — everything is square

  • --ds-radius-control is 0. Buttons, cards, inputs, tiles and images all have hard corners.
  • The only curve in the system is --ds-radius-ring (50%), and it exists for one thing: the ring motif.
  • If a new component wants a rounded corner, the answer is no — square it, or make it a ring.
08 / The ring motif

One circle, always cropped

A thick circular outline, one step lighter than the surface it sits on, cropped off the top-right edge. It is the reference's only decoration, and the system's only piece of ornament.

On light: --ds-ring-color-on-light (#e8dccc) — the same value as the default rule, so it reads as structure rather than decoration.

On light — .ds-ring

Used by .hero__media, .page-head, .split__visual--alt.

On burgundy: --ds-ring-color-on-dark (#481e28) — the ring tint sampled straight from the reference banner.

On burgundy — .ds-ring

Used by .callout and .split__visual.

How it works

  • It is always a pseudo-element (::after): no markup, no layout impact, invisible to screen readers, pointer-events: none.
  • Apply .ds-ring to a block that may be clipped — the class supplies position: relative and overflow: hidden.
  • It must always be cropped. A fully visible ring reads as a logo, which it is not.
  • One ring per band. Never two in view at the same time.

Tokens

  • --ds-ring-color-on-dark / --ds-ring-color-on-light — one step lighter than the surface.
  • --ds-ring-size 520px, --ds-ring-size-compact 320px (≤900px).
  • --ds-ring-thickness 40px, --ds-ring-thickness-compact 24px.
  • --ds-ring-offset-inline -140px and --ds-ring-offset-block -100px do the cropping; both collapse to -64px compact.
  • It replaced the old diagonal hatch textures. Those are gone; don't bring them back.

Rules for dark surfaces

  • Never put logo.svg on burgundy. Use .ds-wordmark, which carries the same text.
  • Button pairing on dark is .btn--dark (cream fill) plus .btn--ghost-on-dark (cream rule). .btn--primary is invisible there — never use it.
  • The footer is one step deeper than the ground, so a dark section can sit directly above it without a seam.
  • A dark band always gets its ring, or none of them do. Don't mix decorated and undecorated burgundy in one view.
11 / Patterns

How blocks combine

Patterns are reusable arrangements of components. Use them as the default — only depart from them with a documented reason.

Hero

  • Bone surface (--ds-color-surface) with a soft radial wash and the ring cropped top-right.
  • Eyebrow over a burgundy hairline, one-sentence headline (an <em> may take the italic tagline voice), one-sentence sub, at most two buttons.
  • Min height 72vh (70vh ≤900px). Content aligns bottom-left. A hero should never feel busy.

12 / Imagery & iconography

Documentary, not heroic

Photography is candid, natural-light, and human. Riders look like riders — not athletes mid-podium. Bikes look used, not staged.

Photography

  • Natural light. Warm, not cool — the image should sit comfortably next to the bone surfaces.
  • Studio interiors, hands-on moments, side profiles of bikes — not raceday action.
  • People comfortable, neutral expressions. No forced smiles.
  • Crop tight and square. Negative space matters more than the subject filling the frame.
  • No rounded corners, no drop shadows, no gradient overlays beyond the system's own washes.

Iconography

  • Line icons only. 1.5px stroke, rounded caps and joins.
  • Single-colour: ink on light, cream on burgundy. Never two-tone, never filled.
  • Match the dashed "fit-line" idiom of the logo when an icon represents measurement or analysis.
  • No gradients and no colour-coded states — burgundy is the only accent available.
13 / Tokens

Three tiers, one file with literals

This page no longer keeps a hand-typed copy of :root — that copy is exactly how a brand book goes stale. The tokens live in one file and this book imports it.

The tiers

  • 1 · Primitive — --ds-<category>-<raw>. Raw, meaningless on its own: --ds-burgundy-700, --ds-scale-24, --ds-lh-160.
  • 2 · Semantic — --ds-<role>-<variant>. Intent-revealing, and always pointed at a primitive: --ds-color-fg, --ds-space-md, --ds-text-lede.
  • 3 · Alias — --color-*, --font-*, --max-width, --gutter. Legacy names kept alive for back-compat; new code uses tier 2.

The rules

  • Literals live only in tokens.css. Everything in base.css, components.css and both entry points goes through tier 2 (or tier 1 for a genuine one-off).
  • Adding a token: add the raw value to the primitive tier, then point a semantic token at it. Never reference a primitive colour from a component.
  • Adding a component: append a block to components.css naming its surface, reuse the .ds-* primitives in markup, and add it to the inventory table. If two components share a declaration block, promote it to a base.css primitive.
  • Check it with the grep below — it must print nothing.
grep -nE "#[0-9a-fA-F]{3,8}\b|rgba?\(" \
  prototype/design-system/base.css \
  prototype/design-system/components.css \
  prototype/styles.css \
  brand/styles.css

A representative excerpt

/* 1. PRIMITIVE — the only file with literals */
--ds-burgundy-700: #3e1420;   /* REFERENCE ground   */
--ds-cream-300:    #edd5b9;   /* REFERENCE wordmark */
--ds-bone-100:     #f7f1e8;
--ds-scale-24:     24px;

/* 2. SEMANTIC — intent, pointed at a primitive */
--ds-color-surface-inverse: var(--ds-burgundy-700);
--ds-color-fg-inverse:      var(--ds-cream-300);
--ds-color-accent:          var(--ds-burgundy-700);
--ds-space-md:              var(--ds-scale-24);

/* 3. ALIAS — legacy names, still live */
--color-accent: var(--ds-color-accent);
--gutter:       var(--ds-gutter);

Where everything lives

  • prototype/design-system/DESIGN-SYSTEM.md — the written system: palette table, hierarchy, ring, component inventory, rules.
  • prototype/design-system/tokens.css — all three tiers, and every literal in the system.
  • prototype/design-system/base.css — reset, element defaults, the .ds-* primitives.
  • prototype/design-system/components.css — every component rule.
  • prototype/styles.css — the site entry point: font import, three layered imports, then the @layer statement. See it running in the prototype.
  • brand/styles.css — this book's entry point: the same three imports by relative path, plus a @layer brandbook of documentation-only styles.

Load order matters. The @layer statement has to sit after the @imports. Chrome drops any @import that follows a @layer statement which itself follows an @import — which silently disables the whole system and renders the page unstyled.
